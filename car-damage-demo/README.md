# Car Damage Assessment — Live Trained-Model Demo

This folder contains the live browser demo plus clean training/evaluation files for the car-damage project.

## Live detector used now

The live page runs the already-trained **YOLOv8 ONNX** detector from:

- Source project: https://github.com/suryaremanan/Damaged-Car-parts-prediction-using-YOLOv8
- Model used by the page: `best.onnx`
- Framework in the original project: YOLOv8 / Ultralytics
- Inference in this demo: ONNX Runtime Web (WASM), directly in the browser
- No Gemini, OpenAI, or other LLM API is used.

### Detector classes

1. damaged door
2. damaged window
3. damaged headlight
4. damaged mirror
5. dent
6. damaged hood
7. damaged bumper
8. damaged wind shield

## Dataset

The source repository includes its labeled YOLO dataset under `data/images/train` and `data/labels/train`. At the time this demo was assembled, it contained **485 images and 485 matching YOLO label files**.

The original `config.yaml` points both `train` and `val` to the same training directory. That is not a defensible academic evaluation split, so the supplied `ml/data.yaml` intentionally corrects this by requiring independent train/validation/test folders.

For the graduation-project version, split the source data (or a larger compatible dataset) before retraining. A typical split is 80% train, 10% validation, 10% test, with duplicate/near-duplicate checking before the split.

## Training

Install:

```bash
pip install ultralytics
```

Then:

```bash
cd ml
python train.py
```

The included training file uses transfer learning from `yolov8n.pt`, 640px images, early stopping, plots, and a fixed seed.

## Evaluation

After training:

```bash
python evaluate.py
```

It reports:

- Precision
- Recall
- mAP@50
- mAP@50-95

Ultralytics also saves evaluation plots (including PR-related plots and confusion-matrix outputs where supported by the task/version). The script exports the final detector to ONNX for deployment.

## Important limitation of the instant web demo

Only the **damage/part detection** is generated by the trained neural network.

The displayed severity and SAR repair-cost figures are deliberately marked as **demo rules**, not ML predictions. They are currently calculated from detected-part type and bounding-box area. They must not be presented in the academic report as trained-model outputs.

The next academic step is to train/validate a separate severity model and a repair-cost regression model on labeled data, then replace those rules.
